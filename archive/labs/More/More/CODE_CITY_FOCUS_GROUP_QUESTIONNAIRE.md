# 🏙️ Code City 2.0 - Focus Group Questionnaire

**Purpose**: Gather qualitative feedback from developers about Code City 2.0
**Format**: Group discussion with guided questions
**Duration**: 60-90 minutes
**Participants**: 5-10 developers of varying experience levels

## 📋 Session Structure

### 1. Introduction (10 minutes)
- Welcome and thank participants
- Explain purpose and format
- Set expectations
- Get consent for recording (if applicable)

### 2. Product Demonstration (15 minutes)
- Show Code City 2.0 features
- Demonstrate scanning process
- Show bug detection
- Display file preview functionality
- Highlight search capabilities

### 3. Hands-on Exploration (20 minutes)
- Let participants try the tool
- Provide sample codebases
- Encourage exploration
- Observe usage patterns

### 4. Guided Discussion (30 minutes)
- Ask prepared questions
- Encourage open discussion
- Probe for details
- Capture all feedback

### 5. Wrap-up (10 minutes)
- Thank participants
- Explain next steps
- Provide contact information
- Offer incentives (if applicable)

## 🗣️ Discussion Questions

### General Impressions

1. **First Impressions**
   - What was your initial reaction when you saw Code City 2.0?
   - How does it compare to other code visualization tools you've used?
   - What stands out as most impressive or innovative?

2. **Concept Understanding**
   - How well does the "code as a city" metaphor work for you?
   - Does the visualization help you understand your codebase better?
   - What mental model does this create for you?

### User Experience

3. **Onboarding**
   - How intuitive was it to get started?
   - What was confusing or unclear?
   - What would make the first-time experience better?

4. **Navigation**
   - How easy was it to find what you needed?
   - Did the tab structure make sense?
   - What navigation improvements would you suggest?

5. **Visual Design**
   - What do you think of the color scheme and styling?
   - Are the animations helpful or distracting?
   - How could the visual design be improved?

### Core Features

6. **Scanning Process**
   - How well did the scanning process work?
   - Was the progress feedback helpful?
   - What scanning options would you like to see?

7. **Bug Detection**
   - How accurate was the bug detection?
   - Were the severity levels appropriate?
   - What additional bug types should be detected?

8. **File Preview**
   - How useful was the file preview feature?
   - Was the error highlighting helpful?
   - What improvements would make this more useful?

9. **Search Functionality**
   - How effective was the search?
   - Did it find what you expected?
   - What search improvements would you suggest?

### Technical Aspects

10. **Performance**
    - How was the overall performance?
    - Were there any noticeable delays?
    - What performance improvements are needed?

11. **Cross-platform**
    - Did it work well on your platform?
    - Were there any platform-specific issues?
    - How could cross-platform support be improved?

12. **Reliability**
    - Did everything work as expected?
    - Were there any crashes or errors?
    - How stable did the application feel?

### Use Cases & Workflow

13. **Work Integration**
    - How would you integrate this into your workflow?
    - What workflow improvements would be helpful?
    - How could this save you time?

14. **Team Collaboration**
    - How could this help with team projects?
    - What collaboration features would be useful?
    - How could this improve code reviews?

15. **Code Quality**
    - How effective is this for improving code quality?
    - What code quality features are missing?
    - How could this help with technical debt?

### Competitive Analysis

16. **Comparison**
    - How does this compare to other tools you use?
    - What does this do better than alternatives?
    - What features are missing compared to alternatives?

17. **Unique Value**
    - What makes Code City 2.0 unique?
    - What problem does it solve that others don't?
    - Why would you choose this over alternatives?

### Future Development

18. **Missing Features**
    - What features are critically missing?
    - What would make this a must-have tool?
    - What advanced features would be valuable?

19. **Integration**
    - What integrations would be most useful?
    - How should it integrate with IDEs?
    - What about CI/CD pipeline integration?

20. **Roadmap**
    - What should be the top priority for development?
    - What would make you recommend this to others?
    - What would make you willing to pay for this?

## 🎯 Focus Group Activities

### Activity 1: Feature Prioritization (10 minutes)
**Objective**: Understand what features are most valuable

**Instructions**:
1. Provide cards with different features
2. Ask participants to rank them by importance
3. Discuss why certain features are more valuable

**Features to Rank**:
- 3D Visualization
- Real-time monitoring
- Collaboration tools
- Advanced bug detection
- Performance optimization
- IDE integration
- CI/CD integration
- Mobile app

### Activity 2: User Journey Mapping (15 minutes)
**Objective**: Understand how users would actually use the product

**Instructions**:
1. Draw a typical user journey on a whiteboard
2. Ask participants to map their workflow
3. Identify pain points and opportunities

**Prompt Questions**:
- Where would Code City fit in your daily workflow?
- What steps would you take to use it effectively?
- What barriers might prevent you from using it?

### Activity 3: Competitive Feature Matrix (10 minutes)
**Objective**: Understand competitive positioning

**Instructions**:
1. Create a matrix with Code City vs competitors
2. Ask participants to fill in strengths/weaknesses
3. Discuss what makes Code City unique

**Competitors to Compare**:
- SonarQube
- CodeClimate
- SourceGraph
- GitHub Code Scanning
- Custom scripts

## 🎬 Discussion Probes

- "What problem did that solve for you?"

- "What didn't work as you expected?"
- "How would you improve that?"
- "What were you trying to accomplish?"
- "What would make that better?"

## 📝 Note-taking Guide

### Key Areas to Capture:
1. **Verbatim Quotes**: Exact words participants use
2. **Non-verbal Cues**: Body language, facial expressions
3. **Group Dynamics**: Who agrees/disagrees with whom
4. **Aha Moments**: When participants understand something
5. **Pain Points**: Frustrations or difficulties
6. **Workarounds**: How participants solve problems
7. **Feature Requests**: Specific improvements suggested
